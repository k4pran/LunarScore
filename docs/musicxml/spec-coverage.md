# MusicXML 4.0 coverage matrix

Audit baseline: 2026-10-15 (MX-00), updated through MX-22 on 2026-10-24. A bounded ordered XML reader, root/security/ZIP probes,
neutral model, diagnostics contract, public [partwise skeleton importer](partwise-import.md) and
[note/rest import](note-import.md) with [attribute state](attribute-state.md), [polyphony, chords and staves](polyphony.md), [timewise normalization](timewise-import.md), [tie/slur resolution](span-import.md) , [beams, stems and tuplets](tuplet-import.md), [directions and note expressions](direction-import.md) [grace/cue notes](grace-import.md), [instruments and pitch interpretation](instrument-import.md) [barlines, repeats and endings](barline-import.md) with separate playback order [layout and visual hints](layout-import.md), [lyrics](lyric-import.md) and a [bounded `.mxl` adapter](mxl-import.md) now exist, and every [4.0 change-list entry](version-40-changes.md) is mapped or reported. The [MX-21 compliance audit](compliance-audit.md) records the adversarial, mixed-feature and public-corpus evidence, the target matrix and the [W3C test-suite results](compliance-audit.md#w3c-musicxml-test-suite-mx-22) (MX-22). Implementation
and tests are reported independently below, distinguishing dependency probes, model projections and
importer coverage. See [dependency evidence](dependency-spike.md) and [model.md](model.md) for

contract-only F22/F23 evidence separately from actual [MX-05 XML reader emission](xml-reader.md). `Verified` requires reviewed
semantic assertions on Android, iOS and JVM where feasible. The [complete element inventory](element-inventory.md)
maps all 442 score-element names plus auxiliary schemas to these groups; attribute/value checklists
remain part of the implementing tasks.

Each change updates the row, links its issue/fixtures and records deliberate loss. Meaningful unsupported content must produce `UNSUPPORTED_FEATURE` with `UnsupportedContent(featureId, retention, sourceXml, conversion)` and a source location; fatal failures report a separate code. A result exposes whether content was discarded, retained opaquely or converted. MX-03 implements this contract; MX-05 emits fatal reader findings and MX-06 emits skeleton semantic findings.
