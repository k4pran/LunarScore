# MusicXML 4.0 coverage matrix

Baseline: 2026-10-13. All features below are **Not implemented** and have **No tests** in the parser. Update implementation and test columns independently when a task lands; `Verified` requires a reviewed semantic assertion on Android, iOS and JVM where feasible. This is a feature-group inventory, not a claim that every XSD element is individually implemented. Expand each group into an element/attribute checklist during its issue.

Status vocabulary: implementation = `Not implemented`, `Partially implemented`, `Implemented`; tests = `None`, `Tested`, `Verified`. Each PR updates the row, links its issue/fixtures and records any deliberate loss. Meaningful unsupported content must produce `UnsupportedFeature(featureId, sourceLocation, retention)`; fatal failures report a separate error code. A parser result should expose whether content was discarded, retained opaquely or converted. The initial checklist should also cover harmony/figured bass, tablature, cross-staff notation, measure repeats, links/bookmarks and sound/listening extensions under the relevant row or a new row before claiming comprehensive compliance.
