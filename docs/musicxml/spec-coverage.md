# MusicXML 4.0 coverage matrix

Audit baseline: 2026-10-15 (MX-00), updated through MX-19 on 2026-10-23. A bounded ordered XML reader, root/security/ZIP probes,
neutral model, diagnostics contract, public [partwise skeleton importer](partwise-import.md) and
[single-voice note/rest import](note-import.md) with [attribute state](attribute-state.md), [timewise normalization](timewise-import.md), [tie/slur resolution](span-import.md) , [beams, stems and tuplets](tuplet-import.md), [directions and note expressions](direction-import.md) [grace/cue notes](grace-import.md), [instruments and pitch interpretation](instrument-import.md) [barlines, repeats and endings](barline-import.md) with separate playback order and [layout and visual hints](layout-import.md) and a [bounded `.mxl` adapter](mxl-import.md) now exist. Implementation
and tests are reported independently below, distinguishing dependency probes, model projections and
importer coverage. See [dependency evidence](dependency-spike.md) and [model.md](model.md) for
exact scope and target results. [MX-03](diagnostics.md) records diagnostic policy, provenance and
contract-only F22/F23 evidence separately from actual [MX-05 XML reader emission](xml-reader.md). `Verified` requires reviewed
semantic assertions on Android, iOS and JVM where feasible. The [complete element inventory](element-inventory.md)
maps all 442 score-element names plus auxiliary schemas to these groups; attribute/value checklists
remain part of the implementing tasks.

Status vocabulary: implementation = `Not implemented`, `Partially implemented`, `Implemented`; tests = `None`, `Tested`, `Verified`. Each change updates the row, links its issue/fixtures and records deliberate loss. Meaningful unsupported content must produce `UNSUPPORTED_FEATURE` with `UnsupportedContent(featureId, retention, sourceXml, conversion)` and a source location; fatal failures report a separate code. A result exposes whether content was discarded, retained opaquely or converted. MX-03 implements this contract; MX-05 emits fatal reader findings and MX-06 emits skeleton semantic findings. See the [case-by-case ledger](risks-and-gaps.md#mx-06-partwise-skeleton-decisions-and-remaining-gaps).

notes, rests, divisions and simple time; their unmapped children are reported individually as
listed in [note-import.md](note-import.md#explicit-unsupported-outcomes). MX-08 adds key, clef and
staff-line state and reports remaining attributes children by owning feature (S08/S16/S17/S23/S24),
as listed in [attribute-state.md](attribute-state.md#diagnostics).
MX-16 replaces the score-instrument, `transpose`, note `instrument`, unpitched-note and whole-`defaults`

MX-17 replaces the barline (S15) and `measure-style` (S24) discard branches with barline, repeat,
ending and measure-repeat interpretation, and reports the remaining content individually as listed
in [barline-import.md](barline-import.md#explicit-unsupported-outcomes).

[layout-import.md](layout-import.md#explicit-unsupported-outcomes).

MX-06 also emits feature-specific discarded-content diagnostics for unmapped notes (S04), cursor
moves (S06), attributes (S07), directions (S13), barlines (S15), score-instrument (S16), defaults/print
(S17), harmony/figured-bass (S22), sound/listening/player/MIDI (S26) and work opus (S27).
`MusicXmlParserTest` tests representative parent rejection/discard under both policies, separately
from the musical interpretation tests still absent in those rows. This does not upgrade those

S22–S27 close inventory omissions; listing existing tasks as owners does not promise full support within those tasks. Where their scope lacks an implementation slice, the required first outcome is a structured unsupported diagnostic and fixture. S20 overlaps domain rows for additions such as `numeral`, `for-part` and `listening`; it is a version-change audit, not a substitute for those rows. `container.xsd` maps to S19, while opus/sound-definition schemas map to S27. Fixture IDs F24–F29 are documented in [test-plan.md](test-plan.md); none exist as executable tests yet.
